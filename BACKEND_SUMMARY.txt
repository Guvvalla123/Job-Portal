--------------------------------------------------------------------------------
SECTION 1 — WHAT THE BACKEND DOES
--------------------------------------------------------------------------------

Express 5 API under /api with versioned JSON at /api/v1 for a job portal: JWT access tokens, httpOnly refresh cookies, CSRF double-submit on mutating routes, job search and recruiter job lifecycle, candidate applications and recruiter pipeline (status, notes, interviews), companies with Cloudinary logos, in-app notifications, candidate job alerts with optional BullMQ email + digest worker, admin stats and moderation, health/ready/metrics probes, optional Sentry.

Roles in code: candidate, recruiter, admin. Register route only allows candidate or recruiter; admin is not created via public register.

Stack: Node >=18, Express 5, Mongoose 9 + MongoDB, Zod validation, optional Redis (cache, idempotency, BullMQ), Cloudinary uploads, Winston logs, prom-client metrics, bcryptjs (cost 12), jsonwebtoken HS256, otplib TOTP for admin MFA.

SECTION 6 — MIDDLEWARE CHAIN
--------------------------------------------------------------------------------

Order in app.js: trust proxy → requestId → logRequest → cors → helmet → compression → hpp → cookieParser → csrfProtection (path /api) → express.json 1mb → urlencoded 1mb → sanitizeInput → (optional) rate limiters → GET /api/metrics → app.use("/api", apiRoutes) → notFound → errorHandler.

Route middleware: requireAuth verifies Bearer HS256 + tokenBlacklist jti; requireRole; validate* Zod 422 UNPROCESSABLE_ENTITY; CSRF compares jid_csrf cookie to X-CSRF-Token; audit wraps res.json; idempotency caches successful POST body replay 24h TTL.

SECTION 7 — AUTHENTICATION DETAILS
--------------------------------------------------------------------------------

Access: HS256; expiresIn JWT_ACCESS_EXPIRES (default "15m"); payload userId, role, amfa; jti per token for blacklist; Bearer header.

Refresh: HS256; expiresIn JWT_REFRESH_EXPIRES (default "7d"); cookie jid_refresh httpOnly path /api/v1/auth; secure in production; sameSite COOKIE_SAME_SITE or strict/lax; User.refreshToken stores sha256 of refresh JWT; new refresh on each /refresh; mismatch clears session and 401 reuse message.

CSRF: jid_csrf readable cookie path / 24h; header x-csrf-token; exempt paths in csrf.js including auth bootstrap routes and reset-password prefix.

RBAC: requireRole; ownership in authorize.js; admin skips selected checks; requireAdminPortalAccess enforces MFA enrollment policy and amfa JWT when mfaEnabled.

Password policy: regex in passwordPolicy.js; bcrypt cost 12.

MFA: otplib TOTP window 1; issuer "CareerSync" in otpauth URL; AES secret encryption MFA_ENCRYPTION_KEY; challenge JWT mfa_chal 5m signed with JWT_ACCESS_SECRET; routes under /auth/mfa/*.

Note: ApiError in utils/apiError.js is (statusCode, message, errors = [], code = null). requireAdminPortalAccess.js uses new ApiError(403, message, "MFA_STEP_REQUIRED", []) and new ApiError(403, message, "MFA_ENROLLMENT_REQUIRED", []). The third argument is a string, not an array, so this.errors is set to []; the fourth argument [] is assigned to this.code. String codes MFA_STEP_REQUIRED / MFA_ENROLLMENT_REQUIRED are therefore not placed in this.code as intended.

SECTION 8 — EMAIL SYSTEM
--------------------------------------------------------------------------------

Primary queue name: email (BullMQ). Worker: src/workers/emailWorker.js requires REDIS_URL or exits 1.

Without REDIS_URL on API: emailQueue uses direct sendMail for known job names and queueEmail legacy; logs warn email_queue_direct_fallback.

Job types: JOB_ALERT, APPLICATION_RECEIVED, APPLICATION_STATUS_CHANGED, INTERVIEW_SCHEDULED, plus raw "send" with to/subject/html.

Retries: attempts 3, exponential backoff 5000ms, removeOnComplete 100, removeOnFail 500.

DLQ: email:dlq after final failure.

Digest worker: src/workers/jobAlertDigestWorker.js requires REDIS_URL; queue job-alert-digest; cron 0 8 * * * UTC (DAILY) and 0 9 * * 1 UTC (WEEKLY); calls jobAlertDigestService.runDigest.

SECTION 11 — PERFORMANCE & CACHING
--------------------------------------------------------------------------------

utils/cache.js: Redis if REDIS_URL and initRedis from server.js; else in-memory Map with 5-minute default TTL for memory path helper; set() uses Redis setex TTL seconds or memory ttl ms = ttlSeconds*1000.

CACHE_TTL in cache.js: jobsList 30 seconds; jobDetail 300 defined but not used by jobService.getJobById (no Redis cache for single job in code).

Jobs list caching: jobService.listJobs caches key jobs:list + JSON.stringify(query) only when page===1 && !q && !location && sort newest && no category/tags/isVerified/postedWithin/employmentType/experienceLevel filters; TTL 30s; probabilistic stale refresh when aged >80% TTL; invalidatePattern("jobs:list") on create/update/delete job, admin job toggles, verify, extend expiry, and resolved job reports.

Idempotency keys: prefix idempotency: — TTL 86400 seconds.

Token blacklist: TTL seconds = remaining JWT exp from logout.

Indexes: Job/Application ensured at startup; models define additional indexes (notifications, jobalerts, companies, audit TTL, etc.).

N+1: admin list endpoints use populate/aggregate; application list paths use repository populates — review changes if adding fields.

Unbounded: repository queries use limit caps in validation (e.g. jobs max 50, applications max 100, notifications max 50 in service); admin lists cap limit 100.
