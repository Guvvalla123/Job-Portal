SECTION 1 — WHAT THE FRONTEND IS
--------------------------------------------------------------------------------
CareerSync is a React single-page application (Vite + React 19) branded as a job marketplace: public job and company discovery, candidate dashboard (applications, saved jobs, alerts, profile), recruiter workspace (jobs, companies, applicant pipeline, interviews), and admin console (users, jobs, companies, applications, audit logs, MFA for admins). It talks to the backend REST API under a versioned prefix resolved in apiClient (default relative base /api/v1 with Vite dev proxy). Authentication pairs short-lived Bearer access tokens in memory with httpOnly refresh cookies and CSRF on mutating requests. Key technical choices: TanStack Query v5 for server state, axios interceptors for bootstrap gating and 401 refresh single-flight, react-router-dom v7 with lazy-loaded route modules, system-driven dark mode (no persisted theme preference), and Sonner toasts for global API errors.

Who uses it: anonymous visitors (browse), candidates (dashboard, apply), recruiters (protected /recruiter/*), admins (protected /admin/*).

How it connects: browser requests use axios apiClient; in development Vite server.port 5173 proxies path /api to target from env VITE_BACKEND_URL or http://127.0.0.1:${VITE_BACKEND_PORT||5000} with changeOrigin true.

Key technical decisions: cookie-based refresh with in-memory access token; React Query default staleTime 30s and refetchOnWindowFocus false (main.jsx); manual Rollup chunks for react, router, query, motion; optional Sentry when VITE_SENTRY_DSN is set.

Dev URL: http://localhost:5173 (vite.config.js server.port; alternate 5174 not configured in repo).

Backend proxy: /api -> target host/port as above (not hard-coded 5174).

Build: npm run build runs node scripts/replace-seo-domain.js then vite build; output directory dist/ (Vite default).

SECTION 5 — AUTH SYSTEM (FRONTEND)
--------------------------------------------------------------------------------
Token Storage:
  Access token: in-memory variable accessTokenMemory in apiClient.js; synced to axios default Authorization header via setAccessToken. Comment in apiClient: "Access token never touches localStorage (XSS)".
  User data: React state in AuthContext (full user from getMe). Minimal snapshot in localStorage key "currentUser" (AUTH_KEYS.USER) via toPersistedSessionUser: { id, role, name } only. Full profile from GET /auth/me in state.
  Session ended flag: key "session_ended" in localStorage (set true on logout path) and read in isSessionIntentionallyEnded() from localStorage OR sessionStorage. Cleared by clearSessionEndedFlag in both storages on login.
  Theme: No localStorage key for user theme preference. Theme follows system prefers-color-scheme via ThemeContext and index.html inline script.

Bootstrap Flow (on app load):
  Step 1: AuthProvider mount calls startBootstrap() synchronously so apiClient requests wait on bootstrapPromise until released.
  Step 2: useEffect runs: if isSessionIntentionallyEnded(), remove AUTH_KEYS.USER and AUTH_KEYS.ACCESS_TOKEN from localStorage (best-effort).
  Step 3: await restoreSessionFromCookie() which calls getRefreshPromise() (POST /auth/refresh with withCredentials) unless session ended; on completion endBootstrap() resolves all waiters.
  Step 4: If no accessToken after restore, clear user, clearSession/clearPersistedAuthKeys, setLoading false, return.
  Step 5: Best-effort GET /auth/csrf-token.
  Step 6: getMe() via GET /auth/me; on success setUser(validatedUser), persist minimal user JSON to localStorage currentUser; on failure clear session and storage.
  Step 7: setLoading(false) in finally when epoch matches.

Bootstrap Lock:
  startBootstrap: Called from AuthProvider body on every render (idempotent — reuses single promise until endBootstrap).
  endBootstrap: Called in restoreSessionFromCookie finally block after refresh attempt completes.
  Purpose: Request interceptor awaits bootstrapPromise (unless skipAuthBootstrapWait) so no API calls run before refresh cookie exchange finishes.

Refresh Flow (on 401):
  authRefreshCoordinator: One in-flight inFlightRefresh promise; concurrent callers reuse same POST; peekInFlightRefresh exposes leader without starting refresh; on failure sets refreshCooldownUntil = Date.now() + REFRESH_FAILURE_COOLDOWN_MS (3000), clearClientAuth, markSessionEnded.
  apiClient uses axios postRefresh with timeout: REFRESH_TIMEOUT_MS (10000).
  Cooldown: REFRESH_FAILURE_COOLDOWN_MS = 3000.
  Timeout on refresh POST: REFRESH_TIMEOUT_MS = 10000.
  Tests: authRefreshCoordinator.test.js (8 cases).

Logout Flow (AuthContext performLogout when logout()):
  If logout already in progress, return.
  Increment authEpoch.
  If redirectToLogin (default true), setSessionEndedFlag() BEFORE server logout.
  POST /auth/logout with optional Authorization header and skipGlobalErrorToast true (unless options.callServer false).
  clearSession(); clearPersistedAuthKeys(); setUser(null); queryClient.clear(); logoutInProgress false; window.location.replace('/login') if redirectToLogin.

Session Persistence Fix:
  Refresh cookie persists server-side; access token in memory only. session_ended in localStorage blocks restore across tabs until cleared on login. Optional read from sessionStorage for the flag per isSessionIntentionallyEnded. localStorage.removeItem on ACCESS_TOKEN is legacy/consistent clearing (token not stored there in normal path).

SECTION 6 — API LAYER
--------------------------------------------------------------------------------
apiClient.js:
  Base URL: resolveApiBase() — if VITE_API_URL empty then "/api/v1"; if absolute URL ends with /api then append /v1; if ends with /v1 use as-is; relative joins with /v1. localhost:5173 in env forces /api/v1.
  Export API_BASE constant with resolved value.
  withCredentials: true (axios default for instance).
  Request interceptor (order): await bootstrapPromise unless skipAuthBootstrapWait; await peekInFlightRefresh if present; setCsrfHeader from jid_csrf cookie for mutate methods; set Authorization from memory; strip Content-Type for FormData; for responseType blob set Accept application/pdf,*/* and delete Content-Type on GET.
  Response interceptor: on 401 with _retry already set: clear session, persist keys clear, setSessionEndedFlag, optional toast, emitSessionExpired; skip refresh for certain auth URLs; if session intentionally ended reject; await bootstrap; if refresh in flight wait and retry once with new token; else call getRefreshPromise(), set _retry, retry once; timeouts set message; global toasts for 401/403/5xx unless skipGlobalErrorToast or auth URL.
  Bootstrap lock: bootstrapPromise shared; restoreSessionFromCookie always startBootstrap in try and endBootstrap in finally.
  _retry: Set to true before initiating refresh retry path so second 401 clears session instead of looping.

authRefreshCoordinator.js:
  Purpose: Ensure only one POST /auth/refresh at a time and propagate result to all waiters; cooldown after failure.
  getRefreshPromise: Starts or reuses inFlightRefresh; validates response data.data.accessToken; applySession on success.
  peekInFlightRefresh: Returns inFlightRefresh without starting refresh.
  REFRESH_FAILURE_COOLDOWN_MS: 3000
  REFRESH_TIMEOUT_MS: 10000
  Tests: authRefreshCoordinator.test.js listed in Section 13.
